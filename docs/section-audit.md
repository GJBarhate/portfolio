## Cross-cutting

| Concern | Finding |
|---|---|
| One rAF, nothing calls `requestAnimationFrame` directly | Verified by exact-string grep (`requestAnimationFrame(`) across `src` — zero call sites outside `raf.js`. The ESLint rule the plan asks be *added* (`no-restricted-syntax` banning bare `requestAnimationFrame`, pointing to `onFrame()`) **already exists** in `eslint.config.js:82-93`, with `raf.js` itself correctly exempted. Nothing to do. |
| No layout read after a write, same frame | Grepped every file combining `onFrame(` and `getBoundingClientRect`. All confirmed read-before-write (or reads confined to a `measure()`/pointer-handler outside the tick), except `ui/ParallaxLayer.jsx`'s `ParallaxLayerJS` fallback, which reads geometry inside its `tick`. That path only runs when `supportsScrollDriven` is false (no native scroll-driven CSS support) and only while the element is `IntersectionObserver`-visible — a documented, scoped, read-before-write fallback for a shrinking population of browsers, not the write-then-read forced-reflow pattern the rule exists to catch. Left as-is. |
| Passive listeners on scroll/touch/wheel/pointermove | Grepped for `addEventListener('scroll'|'touchstart'|'wheel'|'pointermove'`  without a `passive` option anywhere in `src` — zero matches. Already correct. |
| View transitions don't run during scroll | `lib/viewTransition.js` already reasons about exactly this and routes scroll navigation through `scroller.js`'s `scrollTo()`, never `startViewTransition` — its own comment: "A scroll is not a DOM mutation, so a view transition would capture two identical frames." The only `startViewTransition` call site is the Appearance Console's theme-card click handler, never scroll-triggered. |
| `content-visibility` / `contain-intrinsic-size` accuracy | Attempted live measurement; inconclusive in this sandbox. Every `content-visibility:auto` section reported an identical 992px computed height regardless of real content length, which reads as either the "remembered size" mechanism updating from a real prior layout pass, or an artifact of how this embedded Electron/Chromium build's `content-visibility` heuristics differ from stock Chrome — not distinguishable from here. No scrollbar-lurch was directly observed, but the tooling to watch one happen (real compositing, a real scroll) is the same capability this sandbox has lacked all session. Documented honestly rather than guessed at. |

## What this pass changed

- Deleted `src/components/ui/SkillLanes.jsx` (147 lines, zero imports — dead bar-chart component from before Skills was redesigned into grouped-chip cards).
- Deleted `src/components/ui/PhysicsFooter.jsx` (167 lines, zero imports — a matter-js simulation the live Footer never rendered).
- Retired the `physics-footer` entry in `src/lib/effects/registry.js`, matching the file's own existing `film-grain` retirement precedent.
- Removed the now-unused `matter-js` dependency (`npm uninstall matter-js`).
- Fixed a real, reproducible regression: the `64rem–100rem` header nav-cluster band clipped the RESUME link by 48px at 1152px, because the Appearance button's label (added earlier this session, per PLAN.md §5.1) needed more room than the existing spark-counter/recruiter-chip compaction accounted for. Verified empirically with a scripted Playwright check at the exact failing width before and after; `check:layout` is clean across all 17 widths, run twice.
- Fixed a stale end-to-end test (`tests/a11y.spec.js`): it asserted exactly 3 `role="radiogroup"` elements in the Appearance Console, predating the Notices (Do Not Disturb) group added in Phase 2 of this same plan. Updated to 4, re-verified passing.

## What this pass could not independently verify

Consistent with every prior phase's own honesty notes in `PROGRESS.md`: this
sandbox's Browser pane does not composite frames for any tab regardless of
which one is fronted, so `requestAnimationFrame`-driven canvas/game loops,
`animation-timeline: view()`/`scroll()` progress, and framer-motion
`AnimatePresence` exit-transition completion cannot be watched happening
live. Every item above that depends on one of those was either reasoned
about from source (with the reasoning shown) or left unchanged rather than
"fixed" against a guess.

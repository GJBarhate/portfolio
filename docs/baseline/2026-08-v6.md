# Baseline — Portfolio v6, August 2026

**Captured:** 10 August 2026, immediately before Phase 1 of the v6 plan.
**Command:** `npm ci && npm run build` on the tree at the head of `main`.
**Why this file exists:** every claim Phases 1–9 make is a *comparison*. Without
a recorded starting point, "faster" is an opinion. Phase 0 ships no user-visible
change; it exists so the rest of the plan can be argued from numbers.

---

## 0. What is measured here, and what is not

This document is deliberately explicit about the boundary, because a baseline
that quietly conflates measured and estimated numbers is worse than no baseline.

| Measured here | How |
|---|---|
| Per-chunk gzip sizes, all 51 chunks | `npm run build`, gzip of each emitted asset |
| Budget-gate figures | `scripts/check-budgets.mjs` |
| Source-size inventory (CSS lines, selector counts, duplicate/dead rules) | the two new Phase-0 gates + `find-dead-css.mjs` |
| Live WebGL context construction sites | static, from `glStage.js` |
| rAF subscriber bands | static, from the `onFrame` call sites |

| **NOT measured here** | Why, and what stands in for it |
|---|---|
| Lighthouse medians (0.2) | Requires a throttled Chrome run against a deployed origin; not available in the environment this pass ran in. **`lib/rum.js` now collects LCP/INP/CLS/TTFB/FCP with full INP attribution from real sessions**, which is a better instrument than a synthetic median anyway — and it is wired, so the numbers arrive on their own. |
| DevTools performance traces (0.3) | Same reason. The `?perf=1` HUD (0.8) covers the specific questions the traces were wanted for — band starvation, throttled subscribers, live GL contexts, per-effect frame cost — continuously and on the real device, rather than once on a developer's. |
| Long-task inventory (0.4) | The **collection** is implemented (`payload.longTaskBuckets` in `rum.js`, attributed by container, capped at 12 keys). The table below is empty because no production session has reported yet. |

Anything in this file without a number attached says so. Nothing in it is
guessed.

### 2.1 What Phase 0 already fixed in it

The two new gates were written to catch a class of bug, and both caught real
instances on their first run:

| Gate | Found | Fixed |
|---|---|---|
| `check-attr-selectors` | `[data-recruiter='true'] .forge-clock` — a rule that had **never matched**, because the attribute is written as an empty string. This is D-1, and it is why the clock stayed on screen in Recruiter Mode. | → `html[data-recruiter]` |
| `check-css-dupes` | **9 selectors silently clobbering each other**: `.grade-wash`, `::selection`, `:focus-visible`, `.glass--live`, `.about-scene__skeleton`, `.hero-back`, `html[data-recruiter] #hero`, the reduced-motion `.reveal` family, and a fully duplicated `@keyframes heroSprinter` | all merged; the rendered result is unchanged, because in every case the *winning* declarations were kept |

Two of those are worth calling out because they were shipping the wrong thing,
not merely the redundant thing:

- **`:focus-visible`** was written twice with two different ring colours.
  `--accent-bright` was winning; the `--accent` block near the top of the file
  was dead. Anyone reading the top of the sheet would have got the wrong answer
  about the site's focus ring.
- **`@keyframes heroSprinter`** existed twice. The first, in fixed `rem`, was
  entirely replaced by the second, in container units — but it read like the
  live definition, and it is the one that documents the *bug* the second was
  written to fix (the runner leaving frame on a phone).

Neither is visible in a screenshot. Both are exactly what the plan means by
"invisible to every existing gate".

## 3. Runtime — construction sites, statically

### 3.1 WebGL contexts

| Factory | Callers | Contexts |
|---|---|---:|
| `glStage.register` (shared scissor stage) | BackgroundEngine and friends | 1 |
| `createAnchoredRenderer` | `HeroForgeObject`, `ThreeDScene` (About desk), **`MoonForestClock`** | 3 |
| `createDedicatedRenderer` | `FluidCanvas` | 1 |

Not all are live simultaneously — the anchored ones mount and unmount with
their sections — which is precisely why counting them statically is not good
enough. `glStage.liveContextCount()` now tracks the real figure at runtime and
`?perf=1` displays it. **Plan target after 3.9: ≤ 3.**

### 3.2 rAF bands

`raf.js` runs one loop with four groups: `input`, `layout`, `ambient` and the
`critical` exemption. The clock subscribes to **`ambient`** — the first band
dropped when a frame exceeds `FRAME_BUDGET_MS = 24`, and the band that is also
subject to the 1-in-2/3/4 cost throttle and the `window.blur` pause. Composed
with the clock's own 30 fps internal gate, that is the ~10 fps in D-6.

`frameStats()` and `throttledCount()` now expose all of this; `?perf=1` reads
them on a 500 ms interval (not per frame — measuring the subscribers must not
add a subscriber).

## 5. How to reproduce any number here

```bash
npm ci && npm run build          # budgets + per-chunk sizes
node scripts/check-attr-selectors.mjs
node scripts/check-css-dupes.mjs
node scripts/find-dead-css.mjs
```

And on any running instance, append **`?perf=1`** to the URL for fps, frame
time, tier and floor, per-band subscriber counts, throttled-callback count,
live WebGL context count, the current overlay holder, and the clock's own p95
frame cost.

## 6. After — what actually changed

Recorded against §1 above, same commands, same machine.

### 6.1 Budgets

| Budget | Before | Ceiling before | After | Ceiling after |
|---|---:|---:|---:|---:|
| entry | 28.0 KB | 75 KB | 26.6 KB | **60 KB** |
| motion (framer-motion) | 41.6 KB | 45 KB | 41.6 KB | **42 KB** |
| three | 128.9 KB | 135 KB | 129.3 KB | 135 KB |
| eager total | 28.0 KB | 115 KB | 26.6 KB | **95 KB** |
| css total | 45.7 KB | 46 KB | 44.6 KB | **45 KB** |

Every ceiling moved down; none moved up. Two plan targets were **not** met and
the reasons are recorded in `scripts/check-budgets.mjs` rather than absorbed:

- **cssTotal 34 KB** — reached 44.6. The dead-CSS sweep removed ~16 KB of
  *source* (16 spacing utilities, a 12-column grid system, `text-step-*`,
  `fs-*`, `shadow-e*`, `elev-*`, 61 further rules whose entire selector was a
  class no component names, and 15 orphaned `@keyframes`) and that was worth
  1.3 KB gzipped, because gzip is extremely good at repetitive utility CSS.
  Closing the remaining 10 KB means deleting rules that are **live**, which is
  a product decision rather than a performance one.
- **motion 35 KB** — reached 41.6. This chunk *is* framer-motion, so its size
  is a function of the library and not of usage; only removing the last
  consumer removes the chunk. Two consumers went (ExitIntent, and the deleted
  fluid hero); ~15 remain.

### 6.2 Effect budget

| Tier | Before | After | Ceiling |
|---|---:|---:|---:|
| 3 | 5.00 ms GPU | **4.45 ms** | 5 ms |
| 2 | 1.75 ms | **1.56 ms** | 2 ms |
| 1 | 0.00 ms | 0.00 ms | 0 ms |

Tier 3 was sitting at *exactly* the ceiling before this work. Giving the clock
real materials cost 0.65 ms more than the budget had, so the hero fluid
simulation was deleted to pay for it — see `components/ui/FluidHero.jsx` for
the full argument. That also removed the site's only *dedicated* WebGL context.

### 6.4 Two crashes found by the gates, not by review

Both were "Cannot access 'X' before initialization" — a white screen on
**every** production page load — and both were introduced during this pass:

| Where | Cause |
|---|---|
| `App.jsx` | the first-run effect read `recruiter` above its `useState` |
| `AppearanceConsole.jsx` | the auto-close effect read `close` above its `useCallback` |

Neither lint nor the build said anything. `check-overflow.mjs` caught the
first; the a11y spec caught the second. `no-use-before-define` is now enabled
for variables, which would have caught both at author time.

### 6.5 Three more defects the gates found during verification

None of these was on the plan's register; all three were found by a check
rather than by looking.

| Found by | Defect |
|---|---|
| `recruiter-path.spec.js` failing to locate the nav by role | **Every primary nav item had a broken accessible name.** `MorphLink` splits a label into per-character `inline-block` spans so each glyph can animate its own weight; the accessible-name algorithm inserts a separator between block-level children, so "Work" computed as `W o r k` — announced letter by letter, and unfindable by name. The glyphs are now `aria-hidden` and one `sr-only` copy carries the word. |
| Measuring the Appearance Console's geometry in the browser | **`section:not(#hero) { contain-intrinsic-size: auto 800px }` was matching the console's three groups**, and `footer { … }` its footer. The panel's scroll height was 3,380 px for ~640 px of content — the Motion group and the footer sat below a screen and a half of blank space. Both rules are now scoped to `main`/`body`, which is §5.11's "verify the intrinsic sizes" arriving at a real answer. |
| `check-overflow.mjs` | the production bundle crashed on load (see §6.4) |

The console geometry one is worth dwelling on: the panel *screenshotted fine*
in all 36 matrix baselines, because the empty space was below the fold of a
scrolling dialog. A pixel baseline cannot see a layout bug it has scrolled
past; measuring the box could.

### 6.6 Still not measured

Lighthouse medians, DevTools traces and the long-task inventory remain
unmeasured for the reason given in §0 — they need a throttled Chrome run
against a deployed origin. `lib/rum.js` collects the real-user versions of all
three (INP with full attribution, long tasks bucketed by container) and is
wired; the numbers arrive from production on their own.
